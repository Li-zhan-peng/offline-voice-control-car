# 声纹核验：一个如实记录的负结果

> 工程：`<project>`（ESP32-S3 幻尔小车 + 小智离线固件）
> 工具：`<repo>\_voiceprint_proto.py`（参考实现）、`_vp_crosscheck.py`（C 与 Python 对拍）、
> `_voiceprint_eval.py`（错误率评测台）、`_voiceprint_e2e.py`（端到端自动验证）
> 一句话：**我们把设备端声纹做出来了、测了，然后决定不启用它 —— 因为数据说它不行。**

---

## 一、为什么值得公开一个失败的结果

"给小车加声纹，只有主人能指挥它"听起来是个很自然的功能。我们按这个思路做了完整的实现：

- 唤醒词被识别到的那一刻，取三秒环形缓冲里那段音频；
- VAD 选帧 → 25 ms/10 ms 分帧 → 40 维梅尔谱 → DCT 取 c1..c20；
- 时间归一化到 48 帧 + 倒谱均值归一化 → 与注册模板比**余弦**与**DTW**；
- 另算一路**基频 F0**（自相关法）当第三证据；
- 注册：双击 BOOT 键，说 3 遍唤醒词，逐条归一化求平均后以 int16 量化存进 NVS。

整条链路在真机上跑通了（有日志为证）。**但它的分数不成立**，而我们认为把"为什么不成立、
怎么发现的"写清楚，比放一个不敢让人测的功能更有价值 —— 这也是这个仓库存在的意义。

---

## 二、先做对的事情：C 内核与 Python 参考实现对拍

车载端声纹最容易错的从来不是想法而是实现：FFT 下标、梅尔滤波器边界、时间归一化插值、
DTW 初值 —— 错了在板子上只表现为"分数怪怪的"，根本定位不到。

所以 DSP 内核 `voiceprint_dsp.c` 刻意写成**不依赖 ESP-IDF 的纯 C99**（内存分配用一个宏在
PSRAM 与 malloc 之间切换），同一份文件用 gcc 在 PC 上编译，和一个逐行等价的 Python 参考实现
在同一段音频上逐项对比：

```
用例              帧C  帧Py  cos(spec) cos(env)  maxΔspec  maxΔenv   Δf0
flow3_c0           93    93   1.00000  1.00000  1.05e-06  3.19e-06  0.00
...
判定: C 内核与 Python 参考实现【一致】, 可以往板子上搬

DTW 验证: 自己 vs 自己 C=0.000000 Py=0.000000
          变调0.9(冒名代理) vs 本人 C=0.052140 Py=0.052121 -> 方向正确
```

判定标准写死在脚本里（选帧数完全一致、向量余弦 > 0.9999、逐元素偏差 < 5e-3、基频差 < 2 Hz），
不满足就退出码非 0。**这套对拍抓到三个真 bug**：

1. C 侧把 `nullptr` 写进了 `.c` 文件；
2. 基频中位数：C 取"排序后中间那一个"，numpy 的 `median` 在偶数样本时取中间两个的**平均**，
   两者差 **7.7 Hz**；
3. VAD 里的第 20 百分位如果只写个"近似百分位"，选帧就会和参考实现差一帧，后面所有特征
   全不一样 —— 改成和 numpy 完全一致的线性插值定义。

上车之后这套对拍继续有效：**设备报的语音帧数与 PC 用同一段录音重算的帧数完全一致。**

## 三、负结果：主分数测的是"时刻对齐"，不是"是不是同一个人"

把**同一段音频重复播放**（同一个人、同一句话、同一个录音），设备算出来的分数：

| 判据 | 同一段音频重复播放（本人） |
|---|---|
| `cos_spec`（整条谱序列余弦，设计里的主分数） | **−0.21 ~ 0.35**（均值约 0.1） |
| `cos_env`（时间平均谱余弦） | 0.63 ~ 0.99 |
| `dtw`（归一化 DTW 距离） | 0.33 ~ 0.48 |

**同一个人说同一句话，主分数约等于 0。** 而把这段录音做一个变调来冒充，`cos_spec` 反而能到
**0.53 ~ 0.64**，比本人高出十几倍。

原因很干净：`spec` 是"时间归一化后的整条谱序列"拼成一个 960 维向量再算余弦。两段音频只要
**录音时刻对不齐**（环形缓冲切窗位置差几十毫秒），时间归一化出来的序列就错位，余弦立刻掉到 0
附近；而变调冒充用的是**同一段录音**重采样得到的，时刻天然对齐，所以分数反而高。

单独验证过这个解释：在时间归一化后的序列上做 ±8 帧整体平移搜索，本人分数从 0.115 升到 0.239，
**冒充者也同时从 0.528 升到 0.635** —— 平移搜索不解决问题。

PC 上的合成语料实验给出的是同一个结论，而且是四条判据**全部重叠**：

| 实验 | spec 余弦 |
|---|---|
| 本人·加噪 10 dB | 0.76 ~ 0.81 |
| 冒名者·仅变调 0.90 倍 | **0.90** |
| 冒名者·变调 1.10 倍 | **0.915** |

本人加噪的分数**比**冒名者干净的分数**还低**，任何单一阈值都会同时犯两类错（EER 0.375~0.5，
且四条判据分布全部重叠）。

需要如实说明合成语料的局限：现有 TTS 语料只有 2 段不同的音频，所以"冒名集"只能用变调代理，
"本人集"只能用不改基频的扰动（音量/语速/加噪/混响/低通）合成。**这不构成对真人的结论** ——
但它已经足够说明：连"同一段录音变调"这种最有利的冒名都分不开，真人冒名只会更难。

## 四、决定

**不启用**（`VOICEPRINT_ENFORCE` 保持关闭，只记分不改判决，也不设阈值），并把授权能力交给
"口令锁"那一层。理由不是"还没测够"，而是两条独立证据（PC 合成语料四判据全重叠、设备实测
本人分数约等于 0）指向同一件事：**在单麦克风、无阵列的硬件条件下，手工谱特征这条路线不成立。**

顺带说明一个常见误解：这套特征对**信道/录音痕迹**很敏感，对**说话人身份**不敏感。所以它不是
"参数没调好"，而是**特征选错了维度**。

如果还要继续做，真正可行的两条路是：

1. **换成训练过的声纹嵌入模型**（ECAPA-TDNN / ResNet 一类在 VoxCeleb 上预训练的模型，
   量化到 int8 后用 ESP-DL 跑）。这是学界解决"信道差异远大于说话人差异"的标准办法，
   代价是模型移植与 1~3 MB 的 PSRAM 占用。
2. **换一个能成立的用途：防录音回放**。实测里 `cos_env` 对"同一段录音的变调版本"给 0.87~0.96，
   对"不同次真人说话"只给 0.63~0.99 —— 对录音痕迹敏感，正好适合判断"这句话是不是从扬声器
   放出来的"，而不是"这是谁说的"。这条路不用换硬件。

## 五、附带修掉的三个真问题

写"自动端到端验证脚本"的价值就在这里：它把三个靠人试很难定位的问题抓了出来。
（脚本用 SAPI 合成语音 + 电脑喇叭回放，同时抓串口日志和设备经 UDP 发回来的麦克风音频，
再用设备时间戳与墙钟的中位偏移把两边对齐。）

### 5.1 声纹任务爆栈导致整车重启

```
***ERROR*** A stack overflow in task voiceprint has been detected.
Backtrace: ... Rebooting...
```

打分函数里写了 `float tmpl[VP_SPEC_DIM]`（960 个 float = 3.8 KB）的局部数组，而任务栈只有 6 KB，
第一次打分就爆栈。修法：所有 KB 级数组一律放堆（板子上是 PSRAM），任务栈给到 8 KB。

### 5.2 能量门把"连着说的第二句话"挡掉了

噪声底原来是一根 6.4 秒时间常数的单向低通，**说话声音本身会被算进噪声底**。后果是连着说两句时
第二句的能量比从 4.56 掉到 1.69/1.71，低于门限 1.2 直接拒识。改成三段式：比噪声底安静就快速跟上；
不到 2 倍就慢速跟上；明显高于噪声底（是人在说话）就**完全不动**。修完连续 4 次唤醒词全部通过。

### 5.3 I²C 总线被从设备拉住 → 整车失去响应

```
E task_wdt: Task watchdog got triggered ... - IDLE0 (CPU 0)
E task_wdt: CPU 0: heading
Backtrace 反查: heading_task -> qmi8658_read_rawdata -> i2c_master_transmit_receive
              -> s_i2c_send_commands -> i2c_ll_is_bus_busy (原地自旋)
```

总线上的从设备（车头那颗超声波模块是惯犯）在传输中途把 SDA 一直拉低，主机侧看到"总线忙"就在
驱动内层死等 —— **那个自旋不受 `xfer_timeout_ms` 保护**，任务再也回不来，CPU0 上 IDLE 被饿死，
车完全没反应（只刷看门狗）。

修法：新增 `i2c_guard.c`。**判据必须放在发起传输之前**（任务一旦进入自旋就救不回来了）：
每次读写前先读两个引脚电平，发现 SDA 被拉住超过 20 ms 就做标准恢复 —— 把 SCL 当普通 GPIO 打
9 个时钟脉冲让从设备把剩下的位吐完，补一个 STOP，再用 `i2c_master_bus_reset()` 复位主机状态机，
最后把引脚路由用 ROM 的信号连接函数接回 I²C 外设（`gpio_config()` 会把 I²C 从引脚上摘下来，
这一步不能省）。

## 六、复现步骤

```bash
# 1. 合成一个带标注的小语料，验证评测台本身跑得通
python _voiceprint_eval.py --synthetic

# 2. 特征消融实验：一次只改一件事，用同一个评测台量出谁真的有用
python _voiceprint_ablate.py --synthetic

# 3. C 内核与 Python 参考实现对拍（需要 gcc）
python _vp_crosscheck.py

# 4. 设备端端到端自动验证（需要板子连在 COM10；没联网也能跑）
python _voiceprint_e2e.py

# 5. 真实录音评测（先采集：双击 BOOT 注册，再按 采集声纹数据.bat 的说明录）
python _voiceprint_eval.py --dir records
```

第 5 步的判读规则写在脚本里：**只要某一判据的两类分布重叠，单一阈值就不可能同时做到
"不放进冒名"和"不漏掉本人"，这一路就不能单独用于授权判决**；EER 只是重叠程度的折算，
重叠还在时 EER 再好看也不能上线。
