# 授权层：从"能听懂"到"谁有资格指挥"

> 工程：`<project>`（ESP32-S3 幻尔小车 + 小智离线固件）
> 一句话：**唤醒门解决"有没有被叫醒"，口令锁解决"谁有资格下令"，声纹作为第三层加权证据
> ——但实测它不达标，所以只记分不改判决。**

---

## 一、为什么需要这一层

只做语音识别的小车有一个演示现场最容易被问到的问题：

> "那旁边的人喊一句，车不就跑了？"

唤醒词只解决"它有没有被叫醒"——**谁都能叫醒它**。所以需要第二层：**授权**。

我们的做法是三层，每层解决一件事，而且**任何一层失效都不会导致危险动作**：

| 层 | 判据 | 挡什么 | 失效时会怎样 |
|---|---|---|---|
| 1 唤醒门 | "你好小车" 后 20 秒内（车在动时一直有效） | 凭空喊的口令 | 退化为"想到什么说什么"→ 由第 2 层兜 |
| 2 口令锁 | 必须先说「芝麻开门」才放行运动口令 | 别人/噪声乱下令 | 车保持锁定，只是不能用 |
| 3 声纹 | 唤醒词那一段音频与注册模板比对 | 冒充本人 | **实测不达标，只记分不改判决** |

## 二、口令锁的设计规则（每一条都有理由）

| 设计点 | 做法 | 理由 |
|---|---|---|
| 默认状态 | **锁定** | 上电即锁，谁都不能直接开走 |
| 口令 | 「芝麻开门」（拼音 `zhi ma kai men`），进 MultiNet 命令表 | 多字口令比两个字更难被噪声顺口撞上；而且进了命令表就不可能被"听成"别的命令 |
| 生效范围 | **只有运动命令**（前进/后退/左转/右转）；开灯/关灯只要唤醒 | 锁的目的是防止别人把车开走，不是防止别人开灯 |
| 急停 | **不受锁限制** | 任何人在任何状态下都必须能让它停下来 |
| 有效窗口 | 口令后 120 秒，执行运动命令会**自动续期**，超时自动回锁 | 防止演示完忘了锁；也防止正开着车锁突然到期把车停在路中间 |
| 提示区分 | 「车已锁定: 先说 你好小车 → 芝麻开门」与「没听清,请再说一遍」是两种提示 | 否则用户会把"没权限"误当成"识别坏了"，反复喊同一句 |

### 一个被数据否掉的方案：用语音口令触发"注册声纹"

我们原本让用户说「记住我的声音」来开始注册。实测发现 **MultiNet 的词表里没有这个词，
它把这句识别成了「右转」（prob 0.05）** —— 命令窗一开，车就会真的转 90 度。

> **经验**：命令词模型只能识别"它认识的那些词"。往命令表里硬塞一个新词，
> 不会得到"识别不了"，而是会得到"到处乱映射"——这比识别失败危险得多。
> 所以**注册声纹改成了双击 BOOT 键**：它本来就是管理员动作，用物理手势不会误触发，
> 也不受识别率影响，顺带还挡住了"别人喊一句就开始注册"的风险。

## 三、声纹核验：做了、测了、决定不启用

完整数据见 `docs/04-voiceprint-negative-result.md`，这里只放结论：

- 链路已经跑通（注册 3 票 → 模板存 NVS → 重启后仍在 → 打分 120~180 ms，独立任务不占音频线程）；
- 但**把同一段音频重复播放**时，设计里的"主分数" `cos_spec` 只有 **−0.21 ~ 0.35（约等于 0）**，
  而把这段录音做个变调来冒充，反而有 **0.53 ~ 0.64**；
- 跨会话的**类内**分布也很散（`|ΔF0|` 最高到 244 Hz）——
  声纹判决要求"类内紧、类间远"，这里连"类内紧"都不成立。

> 结论：这个特征量测的是"录音时刻对不对齐"，不是"说话人身份"。
> 所以在单麦克风、无阵列的硬件条件下，**它不能用于授权判决**，
> 代码里默认只记分（`VOICEPRINT_ENFORCE=n`）。

## 四、怎么验证（可复现）

口令锁的判决链有一个自动化脚本 `_auth_e2e.py`：用 TTS 通过电脑喇叭按真实时序回放，
同时抓串口日志，逐步核对每一步的行为。

```bash
# 安全模式: 只测"不会让车动"的两步(唤醒 + 急停), 车上可以直接跑
python _auth_e2e.py --safe

# 完整链路: 会让车"以为"自己收到了前进指令 —— 请先把固件编成 bench 模式
# (CONFIG_VOICE_CONTROL_NO_MOTOR=y, 判决链和日志完全一样, 只是不下发电机)
python _auth_e2e.py
```

已用这种方法拿到的证据：

| 步骤 | 结果 |
|---|---|
| 没唤醒就说「前进」 | ✅ 被唤醒门忽略，**没有任何前进动作** |
| 已唤醒但未解锁 + 「前进」 | ✅ 提示「车已锁定」，**没有任何前进动作** |
| 说「芝麻开门」 | ✅ 识别成功并解锁（`>> UNLOCKED`） |
| 解锁后 + 「前进」 | ✅ 执行 |
| 唤醒 → 命令窗打开 | ✅ |
| 急停「停下」 | 待用真人声音补测（喇叭回放时这段音频没被识别成"停下"，是回放识别问题不是逻辑问题） |

**另外建议用真人声音再走一遍**这三步（喇叭回放只能验证判决链，验证不了距离/音量）：

1. 「你好小车」→「前进」 → 应提示「车已锁定」且**车不动**；
2. 「你好小车」→「芝麻开门」→「前进」 → 车才动；
3. 任何时候喊「停下」 → **一定停**。

## 五、这一层最想说的一句话

> 安全功能不是"加一个识别算法"，而是**明确每一个动作在什么样的情况下**不允许发生**，
> 以及**当判断不了的时候默认怎么做**。我们的默认是：判断不了就不动；
> 但"停下"永远放行——因为**误停是安全方向**。
